# UI Automation — Practice Automation

Проект автоматизированного тестирования пользовательского интерфейса сайта [Practice Automation](https://practice-automation.com/) с использованием Python, Selenium, Pytest и Allure.

В проекте используется паттерн **Page Object Model (POM)**, который позволяет разделить логику взаимодействия со страницами и тестовые сценарии.

## Проверяемые страницы

- **Calendar:** https://practice-automation.com/calendars/
- **Modals:** https://practice-automation.com/modals/
- **Ads:** https://practice-automation.com/ads/

Дополнительно реализован тест заполнения поля `Message` списком элементов из раздела `Automation Tools`.

## Используемые технологии

- Python 3.12+
- Selenium WebDriver
- Pytest
- Allure Report
- Google Chrome

Для управления браузером используется Selenium Manager, который обычно автоматически подбирает необходимый драйвер.

## Требования для запуска

Перед началом работы необходимо установить:

- Python версии 3.12 или выше;
- Google Chrome;
- Allure Commandline для просмотра HTML-отчётов.

## Установка проекта

Откройте терминал PowerShell в корневой папке проекта и выполните команды:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Если виртуальное окружение уже создано, повторно создавать его не нужно. Достаточно активировать окружение и установить зависимости.

## Запуск тестов

Запуск всех тестов:

```powershell
python -m pytest -v
```

Запуск тестов календаря:

```powershell
python -m pytest tests/test_calendar.py -v
```

Запуск тестов модальных окон:

```powershell
python -m pytest tests/test_modals.py -v
```

Запуск тестов рекламных окон:

```powershell
python -m pytest tests/test_ads.py -v
```

Запуск дополнительного теста заполнения поля `Message`:

```powershell
python -m pytest tests/test_message_from_automation_tools.py -v
```

По умолчанию браузер запускается в обычном видимом режиме. Для запуска в headless-режиме выполните в PowerShell:

```powershell
$env:HEADLESS="1"
python -m pytest -v
```

Чтобы вернуться к обычному режиму в текущем терминале:

```powershell
Remove-Item Env:HEADLESS
```

## Сценарии тестирования

### 1. Calendar

**Позитивные сценарии:**

1. Проверка успешного открытия страницы календаря.
2. Проверка доступности заголовка страницы.
3. Проверка наличия элемента календаря или поля даты.
4. Проверка доступности поля даты для взаимодействия.
5. Получение текущего значения поля даты.
6. Ввод корректной даты.
7. Изменение ранее введённой даты.

**Негативные сценарии:**

1. Проверка обработки даты в недопустимом формате.
2. Проверка обработки несуществующей календарной даты.
3. Проверка поведения поля при пустом значении.

Проверки ввода выполняются с учётом фактического типа элемента и поведения страницы.

### 2. Modals

**Позитивные сценарии:**

1. Проверка успешного открытия страницы модальных окон.
2. Проверка видимости кнопки Simple Modal.
3. Проверка открытия Simple Modal.
4. Проверка наличия текста внутри Simple Modal.
5. Проверка закрытия Simple Modal.
6. Проверка видимости кнопки Form Modal.
7. Проверка открытия Form Modal.
8. Проверка доступности полей формы.
9. Проверка возможности ввода данных в поля.
10. Проверка закрытия формы и возвращения к странице.

**Негативные сценарии:**

1. Проверка поведения формы при попытке отправки без имени.
2. Проверка обработки некорректного адреса электронной почты.
3. Проверка безопасного повторного закрытия модального окна.

Ожидаемое поведение формы определяется фактической реализацией сайта и браузера.

### 3. Ads

**Позитивные сценарии:**

1. Проверка успешного открытия страницы рекламных окон.
2. Проверка наличия заголовка страницы.
3. Проверка наличия сообщения об обратном отсчёте.
4. Проверка появления рекламного окна после ожидания.
5. Проверка возможности закрытия рекламного окна.
6. Проверка доступности страницы после закрытия окна.

**Негативные и граничные сценарии:**

1. Проверка того, что рекламное окно не считается появившимся без проверки фактического состояния.
2. Проверка отсутствия ошибки при повторном закрытии рекламного окна.
3. Проверка доступности страницы после закрытия рекламного окна.

Появление рекламы зависит от поведения сайта, настроек браузера и наличия блокировщика рекламы. Поэтому отсутствие рекламного окна само по себе не всегда означает неисправность сайта.

## Дополнительное задание: Message / Automation Tools

В проект включён тест `test_message_from_automation_tools.py`.

Тест предназначен для автоматизации следующего сценария:

1. Открыть страницу с формой.
2. Получить средствами Selenium список элементов из раздела `Automation Tools`.
3. Преобразовать полученные названия элементов в текст.
4. Объединить названия через запятую.
5. Заполнить полученным текстом поле `Message`.

Если форма расположена на другой странице, URL можно передать через переменную окружения `FORM_PAGE_URL`.

Пример для PowerShell:

```powershell
$env:FORM_PAGE_URL="https://practice-automation.com/ads/"
python -m pytest tests/test_message_from_automation_tools.py -v
```

При необходимости локаторы в `pages/message_form_page.py` следует адаптировать к актуальной разметке страницы.

## Allure Report

Для запуска тестов с сохранением результатов Allure выполните:

```powershell
python -m pytest --alluredir=allure-results
```

Для просмотра отчёта в браузере при установленном Allure Commandline:

```powershell
allure serve allure-results
```

Также можно сгенерировать HTML-отчёт:

```powershell
allure generate allure-results --clean -o allure-report
allure open allure-report
```

При падении теста скриншот сохраняется и прикладывается к отчёту Allure, если соответствующая логика настроена в `conftest.py`.

## Примечания

- Разметка сайта может изменяться, поэтому при необходимости следует обновлять локаторы.
- Результаты тестирования зависят от доступности сайта, состояния браузера и сетевого соединения.
- Для корректной работы Allure необходимо установить Allure Commandline и Python-зависимости.
- Перед сдачей проекта рекомендуется запустить весь набор тестов и проверить сформированный отчёт.

## Результат выполнения

После запуска Pytest в терминале отображаются выполненные тесты и их статусы: `PASSED` или `FAILED`.

Отчёт Allure позволяет просматривать результаты тестирования и прикреплённые скриншоты ошибок, если они предусмотрены настройками проекта.
